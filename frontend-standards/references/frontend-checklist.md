# Frontend Checklist（通用）

## 端形态
- [ ] 已确认是管理后台、用户端、小程序、H5、App，还是多端复用
- [ ] 用户端新项目默认 uni-app + Vue 3 + TypeScript
- [ ] 即使先做 H5 或小程序，只要后续可能多端，仍优先 uni-app
- [ ] 管理后台默认 Vue 3 + TypeScript + Vite
- [ ] 微信小程序原生仅用于明确长期单端且 uni-app 难以覆盖的平台能力
- [ ] React/Taro 有明确团队或项目原因

## 目录
- [ ] 前端工程与后端工程目录边界清晰
- [ ] uni-app 用户端优先放 `apps/client`
- [ ] `api`、`components`、`pages`、`stores`、`types`、`utils`、`static` 等基础目录职责清楚
- [ ] 复杂业务已按 `modules/{domain}` 聚合
- [ ] 共享包只包含平台无关代码
- [ ] 构建产物不提交到后端业务目录

## 语言与类型
- [ ] 新项目默认 TypeScript
- [ ] Vue 使用 `<script setup lang="ts">` 和 Composition API
- [ ] 接口响应、分页、枚举、表单、路由参数有类型
- [ ] 没有滥用 `any`
- [ ] 常量、枚举、字典项集中管理

## 接口与状态
- [ ] 请求客户端统一处理 token、错误码、超时、登录失效
- [ ] API 层不写页面交互逻辑
- [ ] 文件上传、支付、登录、权限等平台差异已隔离
- [ ] uni-app 平台差异集中在 adapter/composable，页面内没有大段散落 `#ifdef`
- [ ] 页面局部状态和全局 store 边界清楚
- [ ] 管理后台权限覆盖路由、菜单、按钮/操作点

## 体验与交付
- [ ] 加载、空、错误、禁用、权限不足状态齐全
- [ ] 移动端/小程序触控区域和弱网反馈已处理
- [ ] 用户可见文案没有散落重复硬编码
- [ ] 已运行格式化、类型检查、构建或平台预览
